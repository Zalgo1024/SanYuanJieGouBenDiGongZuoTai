# 报告稳定输出方案 v2（回到原点）

> 本版**取代**此前 AI 中心化的 v1。触发纠正：用户指出"我一开始的想法只是给一开始就有的工作流套一层前端"。

## 你点醒的关键
你原本要的，只是给"一开始就有的工作流"套一层前端。那个工作流就是：

```
输入结构化 Markdown  →  export_from_text()  →  确定性输出 docx / pdf / HTML 利益图
```

它**从第一天起就是稳的**——同一份输入永远长出同一份合规报告。

后来的"改进"把 instability 亲手加了进来：
- 把 LLM 当成报告的**生成器**（还设成默认路径），而不是可选助手；
- 搞出 rule / llm / auto 多引擎，同一个按钮行为随配置飘；
- 把"报告规矩"寄托在 AI 软提示上，AI 一偷懒就退化成你否决过的模板味。

你亲历的两种失败，正是 AI 生成路径的必然，不是偶发 bug：
1. **模型抓取外部素材填满报告** → 全是别人的内容，没有你的分析（直接违反你的写作铁律：素材只允许进事实摘要+附录）；
2. **模型压根写不出合规报告** → 降级 / 报错 / 卡死。

这两条在确定性内核上**根本不存在**，因为内核只负责"渲染你给的内容"，不负责"编造内容"。

## 核心原则：撰写与渲染解耦
- **渲染层（稳，确定性）**：`export_from_text` + 渲染器侧结构强制（首章必为"情况概述"、核心冲突点编号+`【主体A】对【主体B】在【利益X】`格式、附录`[名称](url)`、必抽关系图）。喂什么合规 Markdown，都长出一样的合规骨架。
- **撰写层（人）**：报告内容由你（或你审过的草稿）提供。前端就是写内容的工具。
- **AI 草稿（可选、默认关）**：一个"帮我起草"按钮，产出 Markdown 草稿让你改，改完再渲染。**绝不自动把 AI 输出当最终报告交付。**

## 落地步骤（最小改动，不动导出入口 `export_from_text`）
1. **改默认模式**：前端默认 = "我提供内容"（结构化录入 / 粘贴 Markdown），关闭 AI 生成。这一改，报告立刻回到稳定。
2. **保留渲染器侧结构强制**（codex 已加的 overview / conflicts / appendix / diagram 章节）：这是确定性保底，留下，它是好事。
3. **AI 降级为显式按钮**：从默认管线移除，改为可选草稿助手；其输出进编辑器让人审，不直连交付。
4. **加一条渲染回归测试**：固定 Markdown 输入 → 断言输出含必备章节 + 无占位符 + 图存在。护住稳定核心，任何改动不能破它。
5. **前端就只是前端**：录入表单 / Markdown 编辑器 / 提交按钮 / 结果展示页。生成逻辑不该堆在前端。

## 停止做的事（这是 instability 的真正来源）
- 别再调"怎么让 AI 写出符合 spec 的报告"——这是无底洞，越调越飘。
- 别再为 AI 加引擎模式 / 路由分支 / 后校验链——它们本身就是让行为飘的元凶。
- 别让默认管线依赖外部 LLM key 或联网——断网 / 无 key 也必须能出报告。

## 一句话总结
你要的只是"前端壳 + 已有的稳定渲染内核"。把 AI 从"报告生成器"退回"可选草稿助手，人审后渲染"，稳定自然就回来了。之前所有"抓不住重点"的改进，错在把宝押在了 AI 生成上。
