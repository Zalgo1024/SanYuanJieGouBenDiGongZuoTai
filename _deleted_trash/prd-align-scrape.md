## 0. 工作流本质（最高前提，所有需求以此为准绳）

> **用户只输入大概内容/链接，程序从头到尾自动写完整报告（AI 写、内核排），用户不手写成稿。**

- 用户输入 = 关键词 / 一句话主题 / 一个 URL（可多选报告类型）。
- 系统自动完成：联网检索 → 抓取正文 → AI 起草成稿 Markdown → 内核排版 Word/PDF + 三态关系图。
- 用户唯一可选的"事后介入"是展览页的手动改 / AI 再改（D4），不改变"全自动写"这一前提。

---

## 1. 产品目标（一句话）

把 `Web 分析模型` 升级为**本地优先的三元结构理论分析 SaaS**：用户丢关键词/链接即自动联网抓素材、AI 写 5 种类型报告、内核排版 Word/PDF 与三态关系图，报告进入**可下载/可编辑/留痕可回滚的展览页**，全程零手写成稿。

## 3. 用户故事（7 类）

| # | 用户故事 | 核心验收 |
|---|---|---|
| US1 | 作为用户，我希望输入一个主题/关键词后系统自动联网检索素材并写出一篇完整报告，以便我不自己找资料、不手写成稿 | ≥3 条真实可打开来源写入附录；报告含完整章节+关系图+Word/PDF |
| US2 | 作为用户，我希望粘贴一个 URL 后系统自动抓取该页正文作为素材写报告，以便我直接把参考网页变成报告 | 单篇 URL 抓取正文成功；报告内容基于该页素材 |
| US3 | 作为用户，我希望选择政策/事件/组织/舆情/组合 5 种类型后，生成报告的章节骨架与内核渲染类型和我所选一致，以便我得到真正对应类型的深度报告 | 5 类型逐一验证：前端所选类型 = 内核判定类型（双轨护栏） |
| US4 | 作为用户，我希望在报告中看到正确的三态关系图（network/org/flow），一篇可多图，以便我直观理解利益结构、层级与时序 | 多图全展示、布局按 viz 分流、节点类型配色正确 |
| US5 | 作为用户，我希望报告附录每条来源以 `[名称](url)` 形式呈现且可点击，以便我核实事实出处 | Word/PDF/网页三端均可点击跳转 |
| US6 | 作为用户，我希望报告生成后有专门的好看展览页，可下载 Word/PDF、可手动改或让 AI 再改，每次修改留时间戳+摘要+人/AI 标记、可回滚，以便我把报告当正式成果管理 | 版本时间线可回看/回滚；每次修改有留痕 |
| US7 | 作为用户，我希望在前端浏览 cases 案例库，预览成稿正文与关系图、一键套用为模板、直接编辑，以便我参考已验证范文快速产出合格报告 | 案例库列表/预览/套用/编辑四动作全可用 |

## 6. 非功能需求

| 项 | 要求 |
|---|---|
| 本地优先 | 数据全本机（SQLite + reports/ 产物目录）；后端绑 `127.0.0.1` 不对外监听；CORS 仅放行 `127.0.0.1:3000` / `localhost:3000` |
| 检索合规 | 仅抓公开内容（D2）；无登录态、无绕过反爬；DDG 失败时**降级**：提示"检索源不可用，可配置 BING/BRAVE Key 或改用手动 URL 输入"，不静默失败 |
| 密钥安全 | LLM/搜索密钥仅存后端 `.env`，前端**绝不传 api_key**（沿用现有 `AnalyzePayload.llm_config` 约束） |
| 单用户 | 本机单用户，无认证/多租户；登录页 token 仅为前端壳层，不引入权限体系 |
| 可用性 | 一键启动（start.bat）；任务异步 + WS 进度；单篇报告独立下载，PDF 不可用时明确提示 `pdf_unavailable` |
| 数据完整性 | 每次版本保存原子写入；回滚不丢失历史版本 |

## 8. 总体验收口径（发布标准）

1. 双击 `start.bat` → 浏览器 `http://127.0.0.1:3000/dashboard` 打开，5 个页面列表有数据（/api/tasks 生效）。
