# 三元结构理论本地分析工作台架构

## 一、项目定义

本仓库是一个完整的本地分析工作台，由分析内核、FastAPI 后端和 Next.js 前端组成。三部分必须在同一仓库内维护，不依赖相邻项目的前后端源码。

用户从浏览器输入问题、链接或材料；后端创建任务并调用规则引擎或可选 LLM；分析内核把 Markdown 报告导出为 Word、PDF 和关系图；前端展示项目、进度、报告和利益关系网络。数据与密钥只保存在本机。

## 二、组件边界

| 组件 | 目录 | 职责 | 不负责 |
|---|---|---|---|
| 分析内核 | 仓库根目录 | 解析报告、章节路由、Word/PDF/图表导出 | HTTP、页面状态、用户交互 |
| 后端 API | `backend/` | 任务、项目、材料、报告版本、搜索、LLM 编排、内核桥接 | 页面渲染、重复实现分析内核 |
| 浏览器前端 | `frontend/` | 输入、任务进度、项目与报告展示、关系网络交互 | 生成分析结论、伪造后端报告、直接调用内核 |
| 运行时数据 | `backend/data/`、`backend/generated/` | SQLite、配置和生成产物 | 版本控制 |

## 三、运行数据流

```text
浏览器 :3000
  -> POST /api/analyze
FastAPI :8000
  -> SQLite 任务队列
  -> 输入/引擎路由（自由输入走 LLM；结构化输入可走 rule_engine）
  -> engine_bridge
分析内核
  -> Markdown + DOCX + PDF + DIAGRAM
FastAPI
  -> REST / WebSocket
浏览器
  -> 报告、项目、研究账本、分析型关系网络、版本变化与正式产物下载
```

后端数据库和 API 是项目、任务、报告与版本的权威来源。前端本地状态只能作为界面缓存或明确标记的演示数据，不能替代真实分析结果。

## 四、方法论来源

当前运行时方法论由本仓库的 `analysis_prompt.md` 和 `theory_config.json` 提供，`backend/app/prompt_builder.py` 负责装配。仓库外的理论或 Skill 文档不是当前运行时依赖。

未来接入更完整的方法论时，必须先把文件纳入本仓库的版本控制，再建立统一加载器、版本号和自动化测试。禁止把本机兄弟目录或个人绝对路径写成隐式运行依赖。

## 五、仓库边界

1. 默认只在本仓库中搜索、读取、修改和运行代码。
2. 不访问、不复制、不修改相邻的“Web 分析模型 codex”及其他历史工程。
3. 用户明确要求迁移外部资产时，先列出来源、目标和接口适配范围，再执行迁移。
4. `frontend/` 是本项目正式组成部分，不是缓存、快照或临时演示目录。
5. `node_modules/`、`.next/`、虚拟环境、SQLite、生成报告和密钥不进入 Git。

## 六、启动与端口

- 双击根目录 `启动工作台.bat`（推荐）或 `start.bat`：启动前端和后端并打开浏览器。
- 双击 `status.bat`：查看两个服务的实时端口、PID、归属和健康状态。
- 双击 `stop.bat`：只停止命令行可证明属于当前仓库的监听进程。
- 前端：`http://127.0.0.1:3000`
- 后端文档：`http://127.0.0.1:8000/docs`
- 前端默认 API：`http://127.0.0.1:8000`

启动器使用 Next.js 生产模式。`scripts/local-workbench.ps1` 统一负责环境预检、前端构建新鲜度、端口归属、进程复用、健康检查、安全停止和 `.runtime/` 日志。它不会自动改用其他端口，也不会停止无法证明属于本仓库的进程。

## 七、当前已知边界

- 前端生产构建可用，并已建立 Vitest 组件与数据适配测试。
- 主导航收敛为工作台、新建分析和设置；项目目录并入工作台，项目、报告和关系图详情仍保留可直接访问的深层路由。
- 本机运行控制已覆盖启动、重复启动复用、状态检查和安全停止；Windows 服务安装、开机自启与自动更新仍不在当前范围。
- 当前一键体检覆盖 11 项内核测试、后端核心测试、71 项前端测试和 Next.js 生产构建；真实 LLM 与导出端到端测试仍按需单独运行。
- PDF 转换依赖本机 LibreOffice 环境；转换器会在副本文档上工作并保留 Word 原件，但本机环境缺少或锁定 LibreOffice 时仍可能只交付 Word。
- 前端从后端当前报告版本解析全部 `DIAGRAM` 数据，以 `vis-network` 展示 network/org/flow 三类交互图；节点权重、关系强弱/方向/极性/确定性、时间范围与来源数量来自同版本研究快照，选中关系可查看对应判断和来源。
- 报告阅读器以后端版本索引为权威来源，支持历史版本只读预览、回滚、人工修订留痕、语义变化比较以及指定版本 Word/PDF/Markdown 下载；PDF 不可用时前端会保留 Word 下载并显示后端原始错误。
- 研究快照 `schema_version=1.2` 保存来源评级与转载折叠、事实/观点/推断/用户输入、主体档案、关系、时间线、资料缺口、历史对照案例、反事实和定量观察；旧版报告没有研究快照时保持可读，并明确显示为不可核验，而不是补造证据。
- 联网任务会在主查询之外追加历史处置与结果查询，两组来源去重后进入同一证据池。外部观测值必须绑定来源，派生值必须给出公式；缺少条件时数值归一为“未知”。主体数、关系数和有向图谱密度由程序从版本账本直接计算。
- 报告页提供同题对照评测台：本系统快照自动读取，通用模型可用同来源中立提示生成或导入，人工候选可导入；评测只展示主体、证据关系、人工审计事实错误、调查方向和耗时，不合成总分。
- 项目可以配置本机持续追踪频率。后端调度器只在应用运行期间检查到期项目，创建可审计的新任务并比较新旧研究快照；它不是云端常驻服务，电脑关机或工作台停止后不会继续运行。
- 报告网页提供快速版、标准版和完整研究版三种阅读密度。切换只影响展示，不改写数据库中的 Markdown，也不影响正式下载产物。
- 报告阅读器、任务报告预览与编辑器共用安全 Markdown 渲染器，支持 GFM 表格、列表、引用和链接；`DIAGRAM` 原始 JSON 只进入关系图组件，不在报告正文重复展示。
- npm 官方审计当前报告 Next.js、PostCSS 与 Sharp 共 3 个高危项；应用只绑定 `127.0.0.1` 且当前前端未使用 Server Actions，实际暴露面受限，但仍应在上游发布稳定修复版后安排依赖升级与完整回归。
- 当前代码树没有跟踪 `.next` 或构建备份，但旧 Git 历史曾提交多份 `.next_bak` 缓存，导致仓库历史偏大；彻底移除需要单独协调历史重写，不能在日常功能提交中执行。
- GitHub 远程是否可用必须通过 `git remote` 与实际推送共同验证，不能只依赖本地配置。
