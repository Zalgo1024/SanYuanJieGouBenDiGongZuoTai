# 报告写作标准执行设计

## 目标

将 `docs/report-writing-spec.md` 变成所有新报告和 AI 再改报告的生成约束与交付门槛。报告必须是分析骨架，不得把联网素材、空字段说明或自动占位文字交付给读者。

## 范围

- 新生成与 AI 再改报告均适用。
- 历史 `reports/` 目录保持不变；用户指定时才逐篇重跑。
- 同时修复 Markdown 到 Word/PDF 的章节路由，确保概述、证据、冲突和建议不会被单模式渲染静默丢弃。

## 流程

1. 素材上下文只为模型提供每来源不超过五条的事实候选，不再注入整篇抓取原文。
2. 系统提示要求模型在内部完成素材清洗、主体/利益/关系清单；正文只输出概述、3–6 个事实、结构分析与附录来源。
3. 报告以 `情况概述` 开场，随后事实、框架、主体与冲突、三元正文、结论与建议、附录；各类型保留既有的专属分析章节。
4. 质量契约检测素材标记、占位句、缺失概述/命题/冲突/结论/建议/来源、无正文引用的图。失败结果不再自动补“占位章节”。
5. LLM 首次结果不通过时，携带失败项完整重写一次；仍不通过则不把伪完整报告标为合格交付。

## 章节兼容

新增共享 canonical section：`overview`、`evidence`、`core_conflicts`、`recommendations`。它们加入事件、政策、组织与舆情的渲染顺序，避免当前 Word 单模式只渲染 `MODULES` 已知项而丢失内容。

## 验收

- 报告中不存在 `[素材]`、`联网抓取素材`、`（未提供…）`、`（已补占位…）` 等文本。
- 事实摘要有 3–6 项简洁事实；附录每条为 `[名称](url)`。
- 框架有“不是…而是…”核心命题；核心冲突有 3–5 条指定句法；结论有汇流段、核心判断与 3–5 项预判；建议按主体给出可执行动作。
- 关系图从正文主体关系抽取且有正文图号引用；不再生成“占位图”。
- 后端测试、内核章节渲染测试和前端构建通过。
