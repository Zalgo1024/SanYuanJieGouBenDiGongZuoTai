# 网页报告呈现层设计

## 目标

让每份报告在浏览器中先呈现可读的交付摘要，再进入正文和证据，而不是把 Markdown、联网抓取材料和长链接一次性堆在首屏。该能力必须同时服务正式报告页、任务完成预览和报告编辑器预览。

## 边界

- 只修改 `frontend/` 和前端测试；不修改分析内核、后端 API、数据库或既有报告文件。
- 报告 Markdown 仍是后端权威版本；前端只做无损解析和呈现，不生成或改写结论。
- `DIAGRAM` JSON 继续交由利益关系网络页解析，不进入正文阅读流。
- 被抽出的来源和抓取材料必须始终可访问，不能以“精简阅读”为名删除证据。

## 信息模型

新增纯前端 `ReportPresentationModel`，由 Markdown 和报告类型派生：

- `title`：首个一级标题，缺失时回退报告标题。
- `sections`：按一级/二级标题切分的正文段；保留其原始 Markdown。
- `summary`：仅从现有的结论、核心判断、汇流、建议、预判等明确章节提取；若无匹配章节，则使用首段非素材正文作为“阅读起点”。
- `sourceBlocks`：`[联网抓取素材]`、`[素材]` 及显式来源/附录段，不参加默认正文流。
- `hasDiagram`、`sourceCount`、`sectionCount`：用于报告页的交付状态和入口。

所有“核心判断”“阅读起点”等展示均附带跳转到原文段落的锚点，避免摘要脱离依据。无法可靠识别的内容保留在正文，而非强行分类。

## 三个页面

### 正式报告阅读页

顶部保留标题、版本和原有下载/修订/关系图动作。正文区域按下列顺序呈现：

1. 交付摘要：报告类型、核心判断或阅读起点、章节/来源/关系图计数。
2. 正文：左侧只列一级章节；中部以有边界的章节块阅读，每节首段作为导读。
3. 证据与来源：默认折叠，显示来源数；展开后展示联网材料、引用和附录。

版本预览、回滚和下载逻辑保持原样。关系图仍单独进入现有的关系图谱页面。

### 任务完成预览

不再直接铺满整份 Markdown。显示交付摘要、前两个有内容的正文章节和“打开完整报告”入口；用户可在本页展开其余正文及证据与来源。任务尚未产生报告时的空状态保持原样。

### 报告编辑器

左栏保留原始 Markdown 编辑能力。右栏改用相同的 `ReportPresentation` 预览：编辑时实时重新解析，且保持来源折叠。编辑器预览不显示下载、版本或网络图动作，避免与正式交付页混淆。

## 视觉与交互

- 默认只让读者看见交付摘要与正文；来源是显式入口，而不是被删除。
- 正文宽度控制在适合阅读的列宽，章节采用清晰分隔，不增加营销型卡片堆叠。
- 小屏幕下目录转为横向/顶部导航，右栏内容落到正文之后。
- 所有非熟悉图标按钮均保留 `aria-label` 与 `title`。

## 验收标准

1. 含 `[联网抓取素材]` 的报告在默认阅读状态不显示该原始块；展开“证据与来源”后能看到它。
2. 有明确“结论”章节的报告顶部摘要引用该章节内容；无明确结论时使用首段正文回退。
3. 正式阅读页、任务预览和编辑器预览都使用同一解析模型。
4. 历史版本预览、回滚、下载和关系图入口不回归。
5. `npm test` 与 `npm run build` 通过。
