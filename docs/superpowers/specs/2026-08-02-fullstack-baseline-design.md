# 全栈项目基线固化设计

## 目标

把当前本机已经存在的分析内核、FastAPI 后端和 Next.js 前端固化为本仓库唯一、可追踪的全栈基线，消除“Git 认为前端已删除、工作区却存在完整前端”的冲突。

## 范围

本阶段只处理项目身份、文档、版本控制、构建验证和远程备份，不修改分析逻辑、后端接口契约或前端产品行为。

## 决策

1. `frontend/` 是正式产品源码，必须进入 Git；依赖、构建产物和本地环境文件继续忽略。
2. `start.bat` 是本地双端启动入口，当前版本与前端一并纳入基线。
3. `AGENTS.md` 和 `docs/PROJECT_ARCHITECTURE.md` 是项目边界真源，必须明确禁止模型默认访问相邻历史项目。
4. 当前运行时方法论真源是 `analysis_prompt.md` 与 `theory_config.json`；外部 Skill 仅作参考，不声称已经被程序加载。
5. 提交前运行内核测试、后端测试和前端生产构建；PDF 环境波动与前端无测试如实记录，不在本阶段扩大修复范围。
6. 本地提交完成后尝试恢复 GitHub 远程；认证或远程仓库不存在时保留完整本地提交并明确报告阻塞原因。

## 成功标准

- `git ls-files frontend` 能列出前端源码、配置和静态资源。
- `git status` 不再把 `frontend/` 整体显示为未跟踪目录。
- `AGENTS.md` 不再出现“前端已移除”的当前状态描述。
- 架构文档明确内核、后端、前端职责和仓库边界。
- `node_modules/`、`.next/`、`.env*`、数据库与生成产物未被暂存。
- 本地存在一条清晰的全栈基线提交。
- 远程推送成功，或有明确、可复现的认证阻塞记录。
