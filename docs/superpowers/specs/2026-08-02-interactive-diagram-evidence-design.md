# 交互式关系图与证据链设计

## 一、目标与边界

第三阶段把后端当前报告版本中的 `DIAGRAM` JSON 转换为可交互关系图，并在同一页面展示报告引用和任务关联材料。实现只修改 `frontend/`：不新增后端接口，不修改分析内核，不从正文臆测不存在的主体、关系或证据。

## 二、方案选择

采用 `vis-network` 作为图形运行时。它与内核离线 HTML 使用的图形方案一致，支持网络、层级组织和流程布局，以及缩放、拖动、节点/边选择和自适应视口。

未采用的方案：

- 直接嵌入内核生成 HTML：当前 API 没有稳定的图文件服务契约，无法保证版本同步和本地路径可访问。
- 手写 SVG 布局：对多图、环路、缩放和拖动支持不足，后续维护成本高。

## 三、前端数据模型

新增纯函数解析层，将 Markdown 中全部 `DIAGRAM` 代码块规范化为：

- `DiagramDocument`：`id`、`title`、`viz`、`nodes`、`edges`。
- `DiagramNode`：`id`、`label`、`type`。
- `DiagramEdge`：`id`、`source`、`target`、`label`、`type`。
- `EvidenceItem`：报告 Markdown 中的真实链接，或任务明确关联的材料记录。

解析规则：

1. 读取全部 `DIAGRAM` 块，不只读取第一张图。
2. `viz` 仅接受 `network`、`org`、`flow`，未知值降级为 `network`。
3. 坏 JSON、空节点图跳过；指向不存在节点的边丢弃，并在界面显示解析告警数量。
4. 节点、边类型只用于视觉分类，不扩写为额外事实。
5. 报告链接按 URL 去重；关联材料按材料 ID 去重。

## 四、页面结构

利益拆解详情页由四部分组成：

1. **图谱选择栏**：报告含多张图时用标签切换，并显示 `关系网络 / 组织架构 / 流程` 类型。
2. **图谱工具栏**：搜索节点、适应视口、放大、缩小；使用图标按钮和工具提示。
3. **交互画布与检查器**：画布支持拖动、缩放和选择；右侧检查器展示选中节点的类型、入边、出边，或选中关系的来源、目标、标签和关系类型。
4. **证据基础**：分开显示“报告中的公开引用”和“任务关联材料”。它们是报告级证据基础，不宣称与某一节点存在未经后端确认的逐句证明关系。

任务工作台的“关系网络”标签复用同一组件。无合法图时展示明确空状态，并保留查看结构化报告的入口，不退回伪造图。

## 五、布局与视觉语义

- `network`：启用物理布局，适合多主体利益网络。
- `org`：自上而下层级布局，关闭物理模拟。
- `flow`：自左向右层级布局，关闭物理模拟。
- 节点按利益角色分类着色；边按 `economic / power / cultural / legal` 使用不同颜色和线型。
- 主画布保持稳定高度和响应式约束，桌面为画布加右侧检查器，窄屏改为上下布局。
- 页面保持现有安静、研究工作台式视觉，不加入装饰性卡片或营销式说明。

## 六、运行与错误处理

- `vis-network` 仅在客户端动态初始化，组件卸载时销毁实例。
- 报告版本变化时重新解析并重建图，不沿用旧图数据。
- 图运行时加载失败显示错误状态和重试按钮，不影响报告阅读器。
- 解析层返回结构化警告，界面只报告实际跳过的数据，不隐藏损坏输入。

## 七、测试与验收

- 单元测试覆盖多 DIAGRAM、坏 JSON、未知布局、无效边、链接去重和材料证据。
- 组件测试覆盖多图切换、空图状态、节点搜索和证据数量。
- Next.js 生产构建通过。
- 使用真实后端报告在浏览器验证 `network`、`org`、`flow` 三类图可见、非空、可缩放和可选择。
- 桌面与移动视口无文本溢出、画布空白或检查器遮挡。

## 八、非本阶段范围

- 修改后端 DIAGRAM 契约或补写缺失图。
- 自动推断“某句话证明某条边”的段落级证据映射。
- 图谱协同编辑、手工新增节点或写回报告。
- 导出画布截图或独立图谱文件。
