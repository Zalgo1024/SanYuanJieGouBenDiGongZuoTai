# 报告阅读体验与内嵌图谱设计

## 目标

改善报告页四个直接影响阅读的问题：交付摘要留白过大、目录不能随正文滚动定位、定量表暴露内部数据分类标签，以及关系图只能跳转到独立页面查看。

## 设计

### 交付摘要

摘要改为两行网格。第一行左侧显示“交付摘要”，右侧显示正文、来源和图谱数量；第二行由核心判断占满宽度。编辑器和预览模式继续复用同一组件，不增加新的摘要数据来源。

### 滚动目录

新增独立的 `ReportOutline` 组件。桌面端使用 `position: sticky` 保持目录位于视口内，`IntersectionObserver` 观察当前可见章节并为对应目录项设置 `aria-current="location"`。窄屏恢复横向普通流布局，避免占用正文宽度。

### 定量信息

隐藏 `observed` 和 `derived` 的可视徽标，但保留数值、口径、公式、时间与来源。`conflicted` 和 `unknown` 仍显示提示，因为它们表达研究风险而非内部计算过程。

### 报告内图谱

新增 `ReportInlineGraphs`，直接调用现有 `parseReportGraphs`、`enrichDiagramWithResearch` 和 `GraphCanvas`。组件渲染当前报告版本中所有合法 `DIAGRAM`：一张时直接展示，多张时用标签切换；图的数量完全由报告内容决定。完整证据检查仍通过独立关系图谱页完成。

## 边界

- 不修改后端、数据库、分析内核或报告生成规则。
- 不从正文推测或补造图谱；只展示合法 `DIAGRAM`。
- 历史版本使用该版本 Markdown 与研究快照，不混用当前版本图谱。
- 快速版、标准版和完整研究版均可查看图谱。

## 验收

- 摘要核心判断不再被空白首列挤窄。
- 滚动报告时目录保持可见，当前章节自动高亮。
- 页面不显示“观测值”“派生值”，但未知和冲突仍明确标识。
- 一份含三段合法 `DIAGRAM` 的报告显示三个图谱入口，并可逐一切换。
- 前端测试、生产构建和项目一键体检通过。
