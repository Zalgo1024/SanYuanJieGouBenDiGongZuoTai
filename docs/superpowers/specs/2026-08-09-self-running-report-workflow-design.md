# 自运行报告工作流设计

## 一、目标

在保留现有 Next.js 前端、FastAPI API 和 `CaseAnalysisEngine.export_from_text()` 导出内核的前提下，把原先稳定的报告写作流程恢复为后端唯一的自由输入生产链。系统应能在本机独立完成分析，不依赖 Codex、Claude 等智能体参与运行。

## 二、固定生产链

自由输入任务按固定顺序执行：

1. 明确分析范围与证据边界。
2. 把输入和检索材料整理为证据卡片。
3. 生成内部分析底稿：主体、利益、关系和核心命题。
4. 依据报告类型规格生成提纲，并给每节绑定证据编号。
5. 按提纲逐节写作，每次只提供该节所需证据和既有结论。
6. 对完整草稿做一次统稿，消除重复和素材堆砌。
7. 从正文中的主体与关系生成 DIAGRAM。
8. 运行最低交付校验，再交给现有内核导出 Word、PDF 和 HTML。

## 三、运行边界

- LLM 只是受约束的文本生成部件，不负责决定工作流，也不能调用文件、数据库或搜索工具。
- 正式自由输入路径只使用一个已配置模型；模型不可用时明确失败，不回退到规则模板。
- 旧规则引擎暂时保留给现有结构化录入和回归测试，不再作为自由输入报告的降级方案。
- 旧报告只用于本阶段提炼类型规格，不成为运行时依赖。
- 前端页面、路由和 API 响应字段保持兼容，本轮不修改 `frontend/`。
- 不修改 `theory_config.json`，不读取相邻项目。

## 四、报告规格

每种报告类型使用一个轻量 JSON 规格，包含必要章节、章节目的、建议图表和写作提示。章节完整、来源可追溯、DIAGRAM 合法属于硬条件；篇幅、条目数量和文风计数只作为警告，不得因为机械配额销毁整份草稿。

## 五、断点产物

每个任务在 `backend/generated/<task_id>/work/` 保存：

- `input.json`
- `scope.json`
- `evidence.json`
- `foundation.json`
- `outline.json`
- `sections/*.md`
- `draft.md`
- `final.md`
- `diagrams.json`
- `quality.json`
- `state.json`

写入采用临时文件替换，任务重试时从最后一个合法阶段继续。阶段失败保留已完成产物和可读错误，不重跑前置检索与分析。

## 六、最低质量门

硬失败仅包括：正文为空、必要章节缺失或类型明显不符、失败占位句、使用联网材料却没有可点击来源、DIAGRAM 非法。其余写作规格产生警告。允许一次针对具体硬错误的修订；仍不通过时保留 `final.md` 与 `quality.json`，任务标记为需要审阅，而不是删除草稿或改用规则模板伪造报告。

## 七、兼容接入

`ReportGenerator.generate_and_export()` 继续作为队列调用入口。LLM 模式内部改为调用新工作流，返回现有的 `markdown`、`network`、`contract`、`quality`、`engine_used`、模型元数据和导出路径；规则模式与报告再改接口暂时保持不变。
