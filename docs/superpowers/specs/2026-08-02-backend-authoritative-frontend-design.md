# 后端权威前端数据链设计

## 一、目标

前端只展示后端已经保存的项目、任务、材料、报告和报告版本。正常模式不再生成演示项目、模板诊断、虚构证据完整度或本地报告草稿；后端不可用时明确显示连接失败。

## 二、数据真源

- 项目：`GET /api/projects`
- 任务：`GET /api/tasks`，任务实时状态由 `/ws/progress/{task_id}` 更新
- 材料：`GET /api/materials`
- 报告：`GET /api/reports/{task_id}` 取得当前版本，再由 `GET /api/reports/{task_id}/versions/{version_id}` 取得当前 Markdown
- 用户偏好：仅主题、默认引擎和默认导出格式保存在浏览器 `localStorage`

前端内存状态是后端数据的显示缓存，不是第二份数据库。刷新页面后必须重新从后端恢复业务数据。

## 三、运行模式

正常模式默认使用空工作区并连接后端。只有设置 `NEXT_PUBLIC_DEMO_MODE=1` 时才加载 `seed-data.ts`，同时界面必须显示“演示数据”状态，避免把演示内容误认为真实分析。

连接状态分为：

- `checking`：首次读取后端中
- `online`：后端数据已经成功同步
- `offline`：后端请求失败，业务页面不使用旧演示数据兜底
- `demo`：显式演示模式，不访问后端

## 四、任务与报告流程

1. 新建分析调用 `POST /api/analyze`，使用返回的真实 `task_id` 跳转。
2. 任务页若内存中没有该任务，主动从后端任务列表加载。
3. WebSocket报告任务完成后，前端立即读取后端当前报告版本并写入内存。
4. 报告阅读器、编辑器、报告列表和利益拆解入口共享同一个真实报告对象，报告ID统一等于任务ID。
5. 保存修订版本后重新读取后端当前版本，不在前端自行增加版本号或拼装报告。

## 五、界面约束

- 删除按分析类型写死的“当前诊断、风险、关键主体”和由任务进度推算的“证据完整度”。
- 任务运行中只展示后端状态、阶段、进度和用户原始任务标题。
- 任务完成后展示真实报告预览与进入阅读器按钮。
- 后端离线时，在工作台壳层显示明确告警，并提供重新连接按钮。
- 空数据库显示真实空状态，不显示港口扩建演示项目。

## 六、非本阶段范围

- 从 DIAGRAM JSON 构建可交互关系图
- 证据链节点和来源跳转
- 启动器生产化与停止脚本
- PDF环境波动修复

## 七、成功标准

- 默认首次打开时业务数组为空，且不会读取旧业务缓存。
- 后端离线时出现可见告警，不出现演示项目。
- 任务完成事件触发真实报告读取。
- 报告读取使用后端当前版本，而不是前端模板。
- 保存报告后重新同步后端版本。
- 前端自动化测试覆盖空状态、设置持久化、当前版本报告装配、离线状态和任务完成加载。
