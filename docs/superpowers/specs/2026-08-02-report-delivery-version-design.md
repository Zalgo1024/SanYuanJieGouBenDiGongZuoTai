# 报告交付与版本闭环设计

## 一、目标与边界

第四阶段把后端已经具备、但前端尚未完整使用的报告交付能力接入本地工作台：专业阅读、历史版本、指定版本预览、版本回滚、Word/PDF 下载和人工修订留痕。仅修改 `frontend/` 与前端架构文档，不修改后端接口、任务队列、分析逻辑或报告内核。

本阶段的判断标准不是增加更多按钮，而是让一份已完成报告能够沿着“阅读当前版本 -> 检查历史版本 -> 修订生成新版本 -> 必要时回滚 -> 下载正式产物”的路径闭环。

## 二、数据真源

所有版本信息以现有后端接口为准：

- `GET /api/reports/{task_id}`：报告标题、当前版本 ID、版本摘要列表。
- `GET /api/reports/{task_id}/versions/{version_id}`：指定版本完整 Markdown 和元数据。
- `POST /api/reports/{task_id}/versions`：保存人工修订版。
- `POST /api/versions/{version_id}/rollback`：将历史版本回滚为新的当前版本。
- `GET /api/download/{task_id}?kind=word|pdf&version={version_id}`：下载指定版本正式产物。

前端不伪造历史版本、编辑者、时间、摘要或下载状态。回滚成功后必须重新读取后端当前版本和版本列表，不能只在本地改版本号。

## 三、前端模型与适配层

新增报告交付适配模块，统一规范化：

- `ReportVersionSummary`：版本 ID、版本号、类型、编辑者、摘要、备注、创建时间、是否当前。
- `ReportVersionContent`：在摘要字段上增加完整 Markdown 和可选 HTML。
- `fetchReportVersions(taskId)`：读取版本索引并保留后端顺序。
- `fetchReportVersion(taskId, versionId)`：读取指定版本正文。
- `rollbackReportVersion(versionId)`：调用回滚接口。
- `downloadReportArtifact(taskId, kind, versionId)`：读取二进制产物、解析文件名并触发本地下载。

当前 `Report` 对象增加 `currentVersionId` 和 `versions`，工作区首次加载与单报告刷新都由同一适配路径填充，保证报告列表、阅读器、编辑器和关系图使用同一个后端当前版本。

## 四、报告阅读器

阅读器采用三栏工作台结构：目录、正文、版本与交付面板。

1. 正文使用统一 Markdown 渲染器，支持标题、段落、有序/无序列表、引用、表格、链接、粗体、斜体和行内代码。
2. `DIAGRAM` JSON 代码块不作为正文原样展示；图谱仍由利益关系网络页负责呈现。
3. 目录从二级标题生成稳定锚点，不再把正文第一行误当作章节标题。
4. 版本面板展示真实历史记录；选择历史版本后只读预览，并明确标记“非当前版本”。
5. 历史版本可回滚。回滚使用显式确认区，成功后回到新的当前版本并刷新工作区数据。
6. 下载区提供 Word、PDF 和 Markdown 源文件。Word/PDF 走后端正式产物；Markdown 仅下载当前正在预览的源码。
7. PDF 不可用时显示后端错误，不影响 Word 和 Markdown 下载。

## 五、编辑器

编辑器继续保存为新版本，不覆盖旧版本。预览复用阅读器的 Markdown 渲染器；增加独立的版本备注字段，避免把报告标题错误地当成修订说明。页面显示是否有未保存修改，并在保存成功后重新读取后端当前版本。

## 六、视觉与交互

- 保持现有安静、克制的研究工作台视觉，版本记录使用紧凑列表，不使用装饰性卡片堆叠。
- 当前版本、历史预览、保存中、回滚中、下载中、失败和禁用状态必须可辨识。
- 下载格式使用明确命令按钮；历史版本切换使用列表选择；危险操作回滚需二次确认。
- 桌面端正文保持适宜长文阅读的行宽；窄屏时目录、正文和版本面板按阅读顺序堆叠，按钮允许换行且不重叠。

## 七、错误与恢复

- 版本索引或正文读取失败时保留当前已加载报告，并在版本面板显示可重试错误。
- 历史版本读取失败不替换当前正文。
- 回滚和下载错误就地呈现，不使用浏览器原生警告框。
- 组件卸载或快速切换版本时，较旧请求不得覆盖较新选择。

## 八、验收

- 单元测试覆盖版本 DTO 规范化、当前版本识别、指定版本读取、回滚和二进制下载错误。
- 组件测试覆盖 Markdown 表格/链接/列表、DIAGRAM 隐藏、历史预览、返回当前版本、回滚确认和下载状态。
- 全部前端测试、TypeScript 检查和 Next.js 生产构建通过。
- 使用真实本地后端报告验证：至少一份多版本报告可切换、回滚入口可用，Word 可下载，PDF 不可用时错误清楚，桌面与移动布局无重叠。

## 九、非本阶段范围

- AI 自动修订界面、版本差异对比和多人协作。
- WYSIWYG 富文本编辑、批注系统和段落级证据绑定。
- 修改后端版本语义、补生成缺失 PDF 或新增导出格式。
- 图谱截图、图谱编辑或将图谱写回报告。
